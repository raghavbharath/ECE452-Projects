# ECE 452 — Project 2: Optimizing GEMM for Deep Learning with GPU cuBLAS


Benchmarking General Matrix Multiplication (GEMM) across CPU and GPU implementations to study the effect of cache-aware tiling on performance. Compares pure Python loops, NumPy, and NVIDIA cuBLAS across matrix sizes of 128×128, 256×256, and 512×512.

## Usage

### Part 2 — Naive GEMM (CPU)

Run a single size:
```bash
python3 CPU_Naive/gemm-naive.py -s 128 -i 3 -p
```

Run all sizes and generate combined boxplot:
```bash
python3 CPU_Naive/gemm-naive-all.py
```

| Flag | Description |
|------|-------------|
| `-s` | Matrix size (e.g. `-s 256` → 256×256) |
| `-i` | Number of iterations to average |
| `-p` | Save plot |

---

### Part 3 — Tiled GEMM (CPU)

Run a single size and block size:
```bash
python3 CPU_Tiled/gemm-tiled.py -s 512 -b 64 -i 3 -p
```

Run all sizes and block sizes:
```bash
python3 CPU_Tiled/gemm-tiled-all.py
```

| Flag | Description |
|------|-------------|
| `-s` | Matrix size |
| `-b` | Tile/block size (16, 32, 64, 128) |
| `-i` | Number of iterations |
| `-p` | Save plot |

## Results Summary

| Method | 512×512 Avg Time | vs Python Naive |
|--------|-----------------|-----------------|
| CPU Naive (Python) | 75.96s | 1x |
| CPU Naive (NumPy) | 0.0304s | 2,503x |
| CPU Tiled Python (block=64) | 75.73s | ~1x |
| CPU Tiled NumPy (block=64) | 0.01595s | 4,760x |
| GPU cuBLAS | 0.000166s | 457,600x |

---

## Key Takeaways

- Tiling only meaningfully helps when the runtime respects memory layout — Python interpreter overhead swamps any cache benefit in pure loops
- Block size of 64 was optimal given the 48 KB L1 cache — a 64×64 FP32 tile occupies 16 KB, fitting cleanly in L1
- GPU cuBLAS is ~457,600x faster than Python naive at 512×512, showing the combined effect of cache-aware tiling, SIMD vectorization, and GPU parallelism
